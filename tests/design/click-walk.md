## 0. 执行规则

1. **环境**：DSH Desktop（`com.deepseek.dsh`）真实窗口，profile=desktop；Web GUI 直接访问 401，不使用浏览器直连（`docs/ux/prototype.md` §8、spikes S6）。
2. **方式**：open-computer-use MCP —— 每步先 `get_app_state` 取态；优先 `query(text/role)` 精确定位；AX 稀疏时坐标点击兜底（必须配截图）；必要时 `window_placement:'agent_display'` 并在结束 `restore`。
3. **顺序**：1440 主路径 → 负向（禁用/失败/只读/连点）→ 768 窄屏；dark/light 各抽 3 条控件做主题复核。
4. **证据**：每条 = 1 张点击后截图 + DOM/AX 断言文本（属性、文案、计数、`aria-*`）；真实发送类（CW-13/14/16/23 等）另附目标会话事件/内容核对。
5. **判定**：PASS（期望全满足）/ FAIL（任一不满足，写期望/实际/复现步骤）/ BLOCKED（前置不具备或原型/契约未定，写原因）。任何 HIGH 级 FAIL 即验收 FAIL。
6. **数据前置**：测试团队会话（lead + ≥2 teammate + ≥1 活跃 subagent）；测试单 agent 会话（无团队）；只读/归档会话；长消息 fixture（>8 行 / 400 字）。
7. **对齐基线**：`docs/ux/prototype/` 当前快照哈希见 `test-plan.md` §0.2（task-36 锁定 12 张）；走查以 **PRD v0.6.2 / 架构 v1.5 / UX v3.2** + `prototype.md` §7j 为准（入群消息 = 欢迎提示 + creator 带卡消息；只读/筛选见 P11）。

## 2. 覆盖说明（原型缺口 → 走查仍要执行）

以下控件在原型中无画面或无热区（`❌`/`◐`），但 PRD/UX/架构已定义，**实现后仍必须逐条点击**；对应原型问题见 `prototype-review.md`：

- 已补帧/恢复 ✅：筛选提示条/清除（CW-07）、未读浮标（CW-10/11）、只读（CW-17/45）。
- 仍无画面：筛选**菜单**（CW-04/05/06）、复制/打开会话（CW-33/34）、分页（CW-44）、错误/重连（CW-41/42）；单 agent 空态入口（CW-43）已有 P7。
- 原型仅有静态画面的交互（chip 删除、键盘补全、发送中样式、partial 失败清单、卡片展开/收起）也要按规格验证，不能以「原型没画」为通过理由。
